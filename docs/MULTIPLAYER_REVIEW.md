## What each acceptance layer means

The six Editor targets remain **54/24/29/27/22/20**, with zero failed checks or nested errors. The reliability suite uses real sockets inside one Editor process; snapshot fixtures include synthetic states. Neither constitutes independent native multiplayer acceptance. Keep their logs, terminal verdicts and exact source revision.

`tools/native_server_acceptance.py` runs the actual Linux dedicated server with two Python protocol clients and isolated temporary data. It checks gameplay values and controlled restart/persistence as well as security. Python clients are not Unity GUI clients. A diagnostic run that explicitly excludes a failing preservation case is not a complete pass.

Two standalone Unity GUI processes exercise the production transport, bootstrap, command router and presentation independently. The development-only driver is excluded from shipping players. See [native client acceptance](NATIVE_CLIENT_ACCEPTANCE.md) for its procedure and evidence. A normal Linux GUI development-client run does not mean the Windows GUI was executed; the shipping Windows build also requires its own compilation verdict and provenance.

An isolated native canary on DigitalOcean is another gate, using the actual service user and temporary data without joining the production room. Deployment success requires verified backups and secure health against the activated service. Friends connecting from real Windows machines adds the remote-client proof. None of these layers alone is a comprehensive mechanics audit or security certification.

Run **Play-AscendanceMultiplayer.cmd**, enter a distinct player name, then choose **NEW GAME → an unclaimed Hero from the server party → BEGIN ADVENTURE**. Keep the same player name and Windows profile for reconnecting. Unity or an Editor license is not required to play the built client.

The invite's access key belongs only in the private profile and child-process environment. Never publish it, the TLS private material, SSH keys, reconnect data or passphrases in Git, release assets, URLs, logs or chat. Share the invite privately with trusted friends; a shared key is not separate player-account authentication.
